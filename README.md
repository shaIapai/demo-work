## 📌 О проекте

**Data Control Center** — специализированная информационно-аналитическая система, разработанная для Санкт-Петербургского филиала **ООО «ГПК Дерфер»**. 

Система предназначена для непрерывного мониторинга качества данных, автоматической перекрестной сверки информации из разнородных источников, выявления расхождений (весовые характеристики, номенклатура, номера контейнеров, статусы сюрвейерских инспекций) и ведения единого золотого реестра логистических и стивидорных операций.

---

## 🚀 Основные функциональные возможности

### 1. Интерактивный дашборд руководителя (Dashboard)
- Сводные показатели в реальном времени: общий массив записей, процент актуализации, количество инцидентов и критических ошибок.
- Индикаторы статусов распределения данных с контролем диапазона (100% clamping).
- Мониторинг состояния подключенных источников (1С:ERP, WMS терминалов, Telegram-канал тальманов, сюрвейерские акты, внешние БД).
- Динамика выявления и устранения расхождений по дням и типам грузов.

### 2. Единый реестр операций (All Records)
- Консолидированная таблица партий грузов и поручений (зерновые, навалочные, генеральные, химические, контейнерные).
- Гибкая фильтрация по статусам проверки (`Проверено`, `Требует проверки`, `Расхождение`, `Ошибка`), диапазону дат, контрагентам, судам и терминалам.
- Полнотекстовый поиск, сортировка по колонкам и постраничная навигация.
- Экспорт выборок в форматы Excel (`.xlsx`) и CSV.

### 3. Контроль расхождений и инцидентов (Discrepancies & Control)
- Автоматическое выявление нестыковок между источниками (например, вес по коносаменту vs данные весовой терминала vs сюрвейерский отчет драфт-сюрвея).
- **Интерактивное окно ручного разрешения инцидентов (Manual Resolution Modal):**
  - Сравнение значений из разных источников "бок о бок".
  - Выбор эталонного значения или ввод скорректированного.
  - Указание причины изменения, подтверждающего документа и комментариев.
  - Назначение ответственных специалистов и градация приоритетов (`Критический`, `Высокий`, `Средний`, `Низкий`).

### 4. Интеллектуальное сопоставление (Smart Matching)
- Алгоритмы нечеткого поиска и сопоставления записей (Fuzzy Matching) по составным ключам: номер поручения, судно, коносамент, дата судозахода.
- Автоматическая группировка связанных записей и расчет индекса уверенности (Confidence Score).

### 5. Интеграция с Telegram (Telegram Feed)
- Прием оперативных сообщений, весовых сводок и полевых заметок сюрвейеров из Telegram-ботов и чатов.
- Парсинг сообщений с автоматической привязкой к номерам поручений.
- Индикация статуса обработки и возможность мгновенного создания задачи на сверку.

### 6. Управление источниками данных и импорт (Import & Sources)
- Модуль загрузки файлов Excel и CSV с автоматическим распознаванием колонок.
- Мониторинг доступности внешних API, очередей синхронизации и журнала ошибок интеграции.

### 7. Аналитика качества данных (Analytics & QA)
- Расчет метрики качества данных (**Data Quality Index**).
- Среднее время разрешения инцидентов (MTTR).
- Тепловые карты аномалий по категориям грузов, судам и клиентам.

### 8. Аудит и история изменений (Audit Trail)
- Неизменяемый журнал всех действий пользователей: кто, когда и на каком основании изменил значение поля или закрыл расхождение.
- Обеспечение соответствия регламентам внутреннего контроля филиала.

## 💻 Установка и запуск

### Предварительные требования
- **Node.js** версии 18+ (рекомендуется 20 LTS или 22)
- Пакетный менеджер **npm**, **yarn** или **pnpm**

### 1. Клонирование репозитория
```bash
git clone https://github.com/<ваш-аккаунт-или-организация>/data-control-center.git
cd data-control-center
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Запуск в режиме разработки
```bash
npm run dev
```
Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).

### 4. Проверка типов и линтинг
```bash
npm run lint
```

### 5. Сборка для продакшена
```bash
npm run build
```
Собранные оптимизированные статические файлы будут сохранены в папку `dist/`.

## 🔒 Безопасность и регламенты данных

- Приложение разработано с учетом ролевой модели доступа (`Оператор`, `Аналитик`, `Администратор`).
- Все операции по изменению ключевых параметров партий фиксируются в журнале аудита с указанием автора, причины и метки времени.
- При загрузке внешних файлов поддерживается валидация форматов и проверка на дублирование записей.
